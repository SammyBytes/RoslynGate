# Benchmarks

Generated by [`benchmarks/compare.py`](../benchmarks/compare.py) against the
`v0.1.0` Linux x64 release binary and the RoslynGate solution itself.

Environment: Arch Linux, .NET SDK 10.0.402, 5 warm iterations.

## Token volume

| Task | RoslynGate calls | RoslynGate chars | RoslynGate ~tokens | RoslynGate p50 | Grep calls | Grep chars | Grep ~tokens | Grep ms | Token reduction |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| Definition: DefinitionException | 1 | 166 | 42 | 14.2 ms | 1 | 699 | 175 | 10.2 ms | 76% |
| References: DefinitionException | 1 | 909 | 227 | 27.3 ms | 1 | 4917 | 1229 | 10.6 ms | 82% |
| Hierarchy: QueryException | 1 | 198 | 50 | 13.7 ms | 1 | 2099 | 525 | 10.1 ms | 91% |
| Search: Query | 1 | 1356 | 339 | 4.9 ms | 1 | 7672 | 1918 | 10.7 ms | 82% |

`~tokens` is `chars / 4`, an approximation. The baseline uses a single `rg`
call with one or two lines of context. A real agent commonly needs several
searches plus file reads, so this baseline is conservative in RoslynGate's
favor only in the sense that it undercounts the grep workflow.

## Interpretation

- **Token efficiency is clear:** compact, resolved JSON uses 76-91% fewer
  characters than text-search output for the same questions.
- **Warm queries are comparable to grep:** 5-27 ms vs 10-11 ms. The gain is
  token volume and precision, not raw wall-clock speed.
- **The first query pays for MSBuild:** ~14 s for the RoslynGate solution. The
  handshake does not pay it, and prewarm can hide most of it after startup.
- **The 50 ms handshake target is not met:** the machine took ~1.0 s to start
  the MCP host. A minimal MCP SDK host with no tools took ~0.85 s, so this is
  hosting/SDK startup, not workspace loading.
- **Memory:** ~222 MB RSS after loading and querying the solution.

## Caveats

- Characters are not tokens; use a model tokenizer for exact costs.
- Grep output is raw text, not semantic results. The comparison measures
  context volume, not correctness.
- Language, SDK, CPU, and filesystem cache change absolute latency.
- AOT is deferred because `MSBuildWorkspace` is incompatible with it. Startup
  can be revisited with a low-level MCP host or a split process.
