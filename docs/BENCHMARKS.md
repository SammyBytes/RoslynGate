# Benchmarks

Generated by [`benchmarks/compare.py`](../benchmarks/compare.py) against the
`v0.1.3` Linux x64 release build and the RoslynGate solution itself.

Environment: Arch Linux, .NET SDK 10.0.402, 5 warm iterations.

## Token volume

| Task | RoslynGate calls | RoslynGate chars | RoslynGate ~tokens | RoslynGate p50 | Grep calls | Grep chars | Grep ~tokens | Grep ms | Token reduction |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| Definition: DefinitionException | 1 | 166 | 42 | 8.6 ms | 1 | 699 | 175 | 65.0 ms | 76% |
| References: DefinitionException | 1 | 909 | 227 | 11.3 ms | 1 | 5364 | 1341 | 11.7 ms | 83% |
| Hierarchy: QueryException | 1 | 198 | 50 | 9.1 ms | 1 | 2436 | 609 | 10.2 ms | 92% |
| Search: Query | 1 | 1356 | 339 | 3.7 ms | 1 | 7886 | 1972 | 9.9 ms | 83% |

`~tokens` is `chars / 4`, an approximation. The baseline uses a single `rg`
call with one or two lines of context. A real agent commonly needs several
searches plus file reads, so the baseline undercounts the grep workflow.

## Latency and memory

| Metric | Result |
| --- | ---: |
| Handshake, warm filesystem | 333 ms |
| First run, including single-file extraction | ~1.4 s |

| Peak RSS | 266 MB |

## Interpretation

- **Tool-output efficiency is clear:** compact, resolved JSON uses 76-92% fewer
  characters than text-search output for the same questions.
- **End-to-end agent efficiency is workload-dependent:** the two Claude Code
  A/B queries below show 21-34% token reductions for symbol lookups, but they
  also show a large latency cost. The measurements answer different questions.
- **Warm queries are comparable to grep:** 4-11 ms vs roughly 10 ms. The gain
  is token volume and precision, not raw wall-clock speed.
- **The first query pays for MSBuild:** ~11 s for the RoslynGate solution. The
  handshake does not pay it, and prewarm can hide most of it after startup.
- **Startup improved:** the empty host builder plus ReadyToRun cut the warm
  handshake from ~1.0 s to ~0.33 s. The first execution still extracts the
  single-file bundle (~1.4 s).
- **The 50 ms handshake target is not met:** reaching it would require a
  low-level host or AOT. AOT is deferred because `MSBuildWorkspace` is not AOT
  compatible.
- **Memory:** ~266 MB RSS after loading and querying the solution.

## Measure with Claude Code on Windows

The repository includes [`benchmarks/claude-ab.ps1`](../benchmarks/claude-ab.ps1),
an A/B harness that runs the same prompt through Claude Code with and without
RoslynGate and compares the real `usage` tokens:

```powershell
.\benchmarks\claude-ab.ps1 -Symbols "Namespace.TypeA","Namespace.TypeB" -Runs 3
```

See [benchmarks/README.md](../benchmarks/README.md) for details.

For a team member's own prompt, use `-Prompt` instead of `-Symbols`:

```powershell
.\benchmarks\claude-ab.ps1 `
  -Prompt "Find every reference to ViewModels.DatabaseAccess.Doors and answer with file:line" `
  -Runs 3 `
  -Model sonnet
```

This runs the same prompt with and without RoslynGate and reports real tokens,
cost, turns, and duration. It spends real tokens, so use it for representative
prompts rather than every prompt. A skill cannot derive the counterfactual on
its own. Keep prewarm consistent across both arms; the harness copies the
current `.mcp.json`.

### Three-symbol query

Measured on 2026-10-23 with Claude Code and Sonnet against a 99-project legacy
solution (net9.0 plus .NET Framework packages), using `--no-prewarm`, the
default 50-reference limit, and three runs with alternating order. The `with`
arm could use only the four RoslynGate MCP tools; the baseline could use only
`Read`, `Grep`, and `Glob`.

| Metric | With RoslynGate | Without | Difference |
| --- | ---: | ---: | ---: |
| Tokens, median of 3 | 94,158 | 142,506 | 33.9% fewer |
| Cost USD, median of 3 | 0.07 | 0.10 | 30% lower |
| Duration ms, median of 3 | 88,146 | 29,240 | 3.0x slower |

A corrected set comparison found 95 unique RoslynGate references and 98 from
the baseline, with 94 in common. RoslynGate found one reference the baseline
missed (generated Razor code) and missed four that the baseline found.

### Six-symbol query

The second query used fully qualified names to avoid ambiguity, especially for
`Doors`, which appears in several namespaces. It also used `--ref-limit 200`
because the default limit caused incomplete answers for these symbols.

| Metric | With RoslynGate | Without | Difference |
| --- | ---: | ---: | ---: |
| Tokens, median of 3 | 103,904 | 131,865 | 21.2% fewer |
| Cost USD, median of 3 | 0.14 | 0.18 | 22% lower |
| Duration ms, median of 3 | 102,312 | 61,764 | 66% slower |

Set comparison: 167 unique RoslynGate references, 157 from the baseline, and
155 in common. RoslynGate found 12 the baseline missed and missed two that the
baseline found.

The solution took about 24 seconds to load. This is one model, one solution,
and two small queries; treat the numbers as directional, not universal. Token
counts include cache reads; cost comes from Claude Code's `total_cost_usd`. The
latency cost is real: for interactive use, prewarm can move the load earlier,
but it cannot remove it.

## Caveats

- Characters are not tokens; use a model tokenizer for exact costs.
- The table above measures tool-output volume, not end-to-end agent usage. The
  Claude Code A/B is the end-to-end measurement.
- Grep output is raw text, not semantic results. The set comparison filters to
  code files and normalizes paths, but it is not a full semantic proof.
- Reference sets are close but not identical: 95 vs 98 and 167 vs 157. Report
  token reductions with that caveat.
- Language, SDK, CPU, filesystem cache, and the first single-file extraction
  change absolute latency.
